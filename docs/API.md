# REST API v1 — hợp đồng thiết kế

Ngày: 07/11/2026. **Đã có API runtime** trong `apps/api`. Swagger local tại `/docs`, JSON tại `/docs/json`, sinh từ schema thực qua `src/lib/openapi.ts`; 62 path được đăng ký. Request dùng contracts Zod chung, response cốt lõi có schema; response quản trị linh hoạt vẫn dùng envelope mở. Bảng bên dưới là thiết kế Discovery ban đầu; các khác biệt runtime được ghi ngay sau đây và [IMPLEMENTATION_CONTRACT](IMPLEMENTATION_CONTRACT.md) là nguồn tích hợp hiện tại.

## Hợp đồng runtime MVP

Phần simulator bổ sung `depth` khi cast, `drag/rodAngle` khi reel, optional `simulator` trên session và metadata chiều dài/địa điểm/mồi/cần trên catch. GET `/fishing/locations/:id/conditions`, GET `.../community` và POST `.../messages` có xác thực/kiểm tra mở khóa; chat có idempotency/cooldown và chỉ share catch thuộc sở hữu. Hợp đồng chi tiết, giới hạn và tương thích phiên legacy ở [IMPLEMENTATION_CONTRACT](IMPLEMENTATION_CONTRACT.md#fishing-simulator-07112026); mã schema canonical vẫn là nguồn tích hợp.

- Register bắt buộc `{email,username,password,acceptTerms:true}`; mật khẩu8–128 ký tự, đồng bộ login/reset/bootstrap và admin step-up. Không nhận role từ client. Refresh/logout dùng cookie HttpOnly, Origin và `X-CSRF-Token`; access token10 phút ở bộ nhớ client, refresh xoay vòng và phát hiện reuse.
- Mọi request từ web gửi `X-Time-Zone: <IANA>` (ví dụ `Europe/Berlin`); `GET /fishing/locations/:id/conditions` và phiên câu mới dùng giờ địa phương đó cho `hour`. Header thiếu/không hợp lệ dùng `Asia/Ho_Chi_Minh`. Giờ được chụp khi tạo phiên.
- `/users/me` trả trực tiếp PlayerDto trong `{data}`. `/users/me/sessions` trả mảng phiên có deviceLabel/isCurrent, DELETE `/:id` thu hồi cả family. Reset có POST `/auth/reset-password`; forgot nhận email hoặc phone (link qua SMS); thiếu/hỏng SMTP/SMS trả503 rõ ràng. Login nhận `{email|phone,password}`. PlayerDto có `email` (null với tài khoản chỉ số điện thoại, không đổi được) và `phone`.
- Equip/upgrade/use dùng **inventoryItemId**; unequip dùng slot. Upgrade nhận expectedUpgradeLevel. Trang bị LINE/HOOK có thể tháo nhưng cần trang bị đủ để bắt đầu câu. Mồi tiêu thụ ở cast; `/inventory/use` hiện trả ITEM_NOT_SUPPORTED, không giả vờ có vật phẩm tiêu hao ngoài MVP.
- `/fishing/sessions/active` phục hồi phiên; `abandon` có endpoint riêng. SessionDto gồm state/version/serverTime/tension/progress/stamina và catch khi đã commit. Reel nhận `action:hold|release`; mọi action có expectedVersion và Idempotency-Key. Poll/read cũng có thể hoàn tất mô phỏng và lưu catch hợp lệ.
- Shop GET trả configVersion + items; mua nhận expectedUnitPriceGold/configVersion để phát hiện giá cũ. Các list nội dung nhỏ trả `{items}`, leaderboard top100; keyset pagination hiện có cho lịch sử ví (cursor/limit). Chưa tuyên bố mọi danh mục đều có pagination/cache ETag.
- Admin CRUD cho fish/locations/equipment/baits/missions/shop-items. POST nhận `{item:<entry cấu hình đầy đủ>,reason}`; PATCH là allowlist theo loại, active=false archive qua editor giữ lịch sử. Config draft/publish có expectedActiveVersion và audit. Bootstrap SUPER_ADMIN đầu tiên qua CLI; API PATCH `/admin/users/:id/role` nhận role/password/reason, đòi SUPER_ADMIN xác nhận lại mật khẩu và bảo vệ admin cuối cùng. Giao diện cấp role nâng cao/MFA nằm backlog. Không có event engine.
- Analytics được ghi PostgreSQL và dashboard đọc aggregate; chưa có worker xuất dữ liệu ra dịch vụ ngoài. Client telemetry không cấp phần thưởng. `/health` kiểm process, `/ready` kiểm DB và Redis nếu cấu hình.

Auth email/password dưới đây là hợp đồng phát triển nội bộ; chưa đủ cho beta/public tại Việt Nam. [LEGAL.md](LEGAL.md) xác định gate trước phát hành; cần bổ sung API định danh/tuổi/người giám hộ/thời gian chơi sau khi phạm vi pháp lý được xác nhận, không thu dữ liệu thật trước khi thiết kế privacy được duyệt.

## Quy ước dùng chung

- Base `/api/v1`, JSON UTF-8; ISO-8601 UTC; ID UUID; Gold là chuỗi số nguyên thập phân ở cả request/response (validate regex/range rồi parse BigInt); weight số nguyên gram. IDs trong URL phải UUID hợp lệ. Slug như `ho-sen`, `carp` là khóa seed/config, không thay UUID trên route.
- Thành công `{ data, meta?: { nextCursor, serverTime } }`; lỗi `{ error: { code, message, requestId, fields?, formErrors? } }`. `fields` là map đường dẫn field → mảng thông báo; `formErrors` chứa lỗi không gắn được với field. Client giữ cấu trúc này để hiển thị inline. Không echo secrets hoặc stack trace. GET list nhận `cursor?`, `limit` 1–100 (default 20); keyset stable, cursor opaque validate.
- Auth `P`: Bearer access token và active account; `A(role)`: P + role trong DB; `R`: refresh cookie HttpOnly + CSRF header/origin; `—`: public. Ownership kiểm tra mọi resource player, trả 404 để không dò ID người khác.
- Mọi mutation kinh tế/gameplay nhận `Idempotency-Key` UUID; lưu scope user+endpoint+key, request hash và response trong DB transaction. Cùng key khác body → 409 IDEMPOTENCY_CONFLICT, cùng body trả nguyên response. Thời gian lưu ít nhất 24h; unique business references trong ledger/catch/claim giữ lâu hơn.
- Common errors: 400 VALIDATION_ERROR; 401 UNAUTHENTICATED; 403 FORBIDDEN/CSRF_FAILED; 404 NOT_FOUND; 409 CONFLICT; 429 RATE_LIMITED (`Retry-After`); 503 DEPENDENCY_UNAVAILABLE. Reject unknown fields, string limits, `additionalProperties:false`; không nhận reward/rarity/gold từ client.
- Public config chỉ trả dữ liệu mô tả, không trả hidden spawn weights/server snapshots. Cache theo ETag/configVersion cho danh mục; auth, wallet, session trả no-store.

## Fishing

`SessionPublic={id,state,version,serverTime,locationId,tension,progress,hookDeadline?,catch?}`. Không trả biteAt trước BITE hoặc fish/reward trước CAUGHT. `expectedVersion` nguyên không âm bắt buộc cho cast/hook/reel/complete.

| Method + path                       | Auth | Request + validation                                                                     | Response                                                        | Lỗi nghiệp vụ / quyền                                                                                                                          |
| ----------------------------------- | ---- | ---------------------------------------------------------------------------------------- | --------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| POST /fishing/sessions              | P    | `{locationId,baitInventoryId}`; owned equipped rod và bait tương thích                   | 201 `SessionPublic` IDLE                                        | 409 ACTIVE_SESSION `{sessionId}`; 422 LOCATION_LOCKED/INVALID_EQUIPMENT/NO_BAIT/INSUFFICIENT_GOLD; entry fee debit có ledger                   |
| POST /fishing/sessions/:id/cast     | P    | `{expectedVersion,aim:0..1,power:0..1}`; animation input bị clamp/validate, không reward | `SessionPublic` CASTING rồi WAITING theo server clock           | 409 INVALID_STATE/VERSION_CONFLICT; cast tiêu hao mồi đúng một lần                                                                             |

| GET /fishing/sessions/:id           | P    | UUID                                                                                     | `SessionPublic`; process due transitions/timeouts trước khi đọc | 404 owner mismatch; không cần mutation từ client để cá thoát khi quá hạn                                                                       |

Catch response `{id,species,weightG,rarity,gold,xp,newLevel,collectionRecord,walletBalanceGold}` chỉ được sinh sau commit. Client retry timeout GET session/receipt; không tự cộng tiền optimistic. Việc poll có thể làm version đổi do server transition; client dùng version mới nhất và xử lý 409 bằng refetch, không retry hook muộn vô hạn.

## OpenAPI và nghiệm thu

Foundation tạo Zod schemas dùng chung contracts, Fastify validator/serializer adapter phù hợp phiên bản đã pin; generate OpenAPI 3.1 (hoặc 3.0 nếu toolchain yêu cầu, ghi ADR) bằng `@fastify/swagger` và Swagger UI có access control ở staging, tắt public admin schema ở production. Mỗi operation có operationId, tags, security, strict request/response/error schema và ví dụ không có secret.

Contract check phải xác minh mọi route thực tế có schema; integration test so response serialize, status, idempotency và authorization với hợp đồng này; không coi Markdown là OpenAPI executable. Mọi lệnh tạo OpenAPI sẽ chạy bằng pnpm trong apps/api khi module tồn tại.
